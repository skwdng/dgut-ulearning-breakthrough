## 2. 这一轮（10-31 ~ 11-19）发生了什么

按重要性排序，每条都有代码/日志/实测依据。

### 2.1 启动闪退：已修复并进正式版

- 根因：`AndroidManifest.xml` 里 `NotificationListenerService` 写成相对名 `.delivery.…`，按 namespace 展开成 `com.lifekit.app.test.delivery.*`，而 Kotlin 类实际是 `com.lifekit.delivery.*` → 每次启动 `handleCreateService` 抛 `ClassNotFoundException` 杀进程
- 修复：写全名 `com.lifekit.delivery.DeliveryNotificationListener`；wire-native 模板同步；新增 `tools/verify-delivery-listener.cjs`（清单/模板/Kotlin package/dex 四处一致）
- 验证：正式版 APK 里 `aapt2 dump xmltree` 确认全名；服务器日志里 1.1.7 启动打点齐全、无 native_crash

### 2.2 投票/答题：接口层修好了，但"结束后补交"这条路是死的

已修正（全部依据 H5 一手代码 + 无凭据实测）：
- 活动列表必须走 `/courseapi/wisdomClassroom/student/classroomActivitys`（原写成 `/classroomapi`）
- 答题走 `SMART_API_HOST` = `application.dgut.edu.cn/classroomapi`（App 里用 `/smartapi` 前缀映射，lms 域 `/classroomapi` 兜底）
- 答题详情要读 `result.replyquestion`（JSON 字符串）里的 type/status；`options` 在 `result` 层；`myAnswer/correctAnswer` 是 **value 串**
- 答题提交 `optionIds` 传 **option.id**（H5 先 value→id）
- 投票 `myVoted` 是**数组**、响应**没有** `isOver`，结束只看 `vote.endDate`
- 票数显示 0 的假象：`classId` 传 -1 时服务端返回空统计（`studentCount` 有、`votedCount` 全 0）。教学班 classID 从签到详情 `classez[].classID` 取，不是课程列表的 classId

**⚠️ 一次数据事故（务必读）**：
`POST /apps/voteV2/restart/{voteId}`（重开投票）**不是"重新打开"，而是重置活动统计**。一次调用把某投票票数从 42/43/12 清成 0/0/0，`end` 改不回来。
→ UI 里的「重开活动 / 恢复为已结束」已**全部删除**；`interactionApi` 保留函数但注明"会清空数据、勿接回界面"；`tools/verify-vote-feature.cjs` 有反向断言。

**现状**：正式版**不含**投票/答题入口（按版本号 `-test` 自动隐藏，见 `config/buildConfig.ts` 的 `isTestBuild`）；测试版才有，且只读为主。

### 2.3 改签到状态：平台补了权限校验，"补签已结束点名"失效

- App 的「改状态」按顺序试 5 个接口，第一个是教师接口 `signByTea`
- 历史实测（`signApi.ts:190`）：`signByTea` 曾经**对学生没有权限校验** → 所以以前能补签已结束的点名
- 2026-11-19 起服务端返回 `无权限操作该点名` → 教师接口被拦
- 学生接口 `signByStu` 对已结束点名本来就返回 `status=202（点名已结束）`（`youxue-api-verified.md` 4.4 有完整状态码表）
- **结论**：只有**进行中**的点名能改；已结束的补签不了，这是平台策略，App 侧无解

### 2.4 校外访问被拦：学校出口加了 DPtech

- 从校外访问 `lms.dgut.edu.cn` 现在返回：
  ```
  HTTP/1.1 302 Temporarily Moved
  Server: DPtech
  Location: https://nic.dgut.edu.cn/fwsxym.htm
  ```
- App 表现为"服务端 HTTP=200 返回 HTML"→"没有取到课程列表"（跟随 302 拿到说明页）
- 学生实际反馈："连了校园网就直接进了"
- **处理**：连校园网或学校 VPN；App 侧可把这种响应识别成"需要校园网/VPN"的明确提示（尚未实现）

### 2.5 点不中：入口关闭

- 用户要求对外公告"维护中，暂已关闭通道"
- 现状：入口不显示；页面 `/dianbuzhong` 与路由保留；「小操作 → 课堂互动」里有一行「维护中」提示
- 恢复方法：把 `src/screens/xiaocao.tsx` 里注释掉的 OpRow 放回来

### 2.6 体验层改动（正式版已包含）

1. 首页「换背景照片」整块可点 → 固定按钮（防误触）

## 4. 坑清单（越靠前越贵）

1. **restart = 重置统计**（见 2.2）。任何"重开活动"类接口一律视为破坏性。
2. **改状态的教师接口已被封**（见 2.3）。别再假设"补签已结束点名"可行。
3. **校外访问 302 到 nic.dgut.edu.cn**（见 2.4）。所有接口失败先确认是不是没连校园网。
4. **`classId` 传 -1 会拿到空统计**，看起来像"数据被清空"，实际是查询维度不对。
5. **投票 `myVoted` 是数组**，`Boolean([])` 恒 true，会误判"已投过"。
6. **答题详情在 `result` 层**，`replyquestion` 是 JSON 字符串，不 parse 读不到 type/status。
7. **`signByTea` 曾经学生可调**——历史注释里的"实测"可能已过期，改这块前先只读验证。
8. **正式版/测试版靠版本号区分功能**（`isTestBuild` 看有没有 `-test`），别用 env（`EXPO_PUBLIC_*` 在 release 里不内联，踩过坑）。
9. **APK 不进 git**（`*.apk`、`server/apk/` 在 .gitignore）；APK 与 `version.json` 必须成对上传。
10. **GitHub SSH 22 不通**，用 `ssh://git@ssh.github.com:443/...`。

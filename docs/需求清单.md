## 三、已明确「不做」

| # | 需求 | 原因 |
|---|---|---|
| N0 | **「已结束后提交投票/答题」**（用户 2026-10-30、10-31 多次要求） | **技术上不可行，且试错已造成一次数据事故（2026-10-31）**：① 直接提交被服务端拒（投票 `{"success":false,"status":202}`、答题 `code 201`）；② 唯一有路由证据的绕法是 `restart`（重开活动），实测它 = **重置投票统计**，某投票票数从 42/43/12 变成 0/0/0，且 `end` 只能改状态、票数回不来（已确认被覆盖）。所以 UI 里的「重开活动 / 恢复为已结束」已全部移除，`interactionApi` 里保留函数但注明"会清空数据、勿接回界面"。**任何"重开活动"类接口一律视为破坏性操作。** |
|---|---|---|
| N1 | 投票/答题**已结束后**提交或修改（用户 2026-10-30、2026-10-31 两次提出） | **做法已改（2026-10-31）**：客户端不再拦截，界面照常给选择/提交按钮，请求直接发给服务端，由平台判定。依据是 H5 `stuSubmitAnswer` 的提交回调里就写了 `201 = 活动已结束`、`203 = 活动不存在` —— 拦截发生在服务端，客户端拦不拦都不改变结果，拦了只会让人分不清"本地限制"还是"平台拒绝"。提交失败时界面显示服务端原话。 |
| N2 | 虚拟跑步/运动数据伪造 | 用户多次提过，已多次拒绝（伪造运动数据，平台要求真实性） |
| N3 | 考试自动答题 | 已拒绝；只提供题库查询等不作弊的替代 |
| N4 | LifeKit 多账号切换 | 用户明确"每个人只能搞自己的" |
| N5 | LifeKit 加「优学院中国站」登录 | 用户明确改到 u学院辅助（uassist）里做；LifeKit 保持东莞理工单站点 |

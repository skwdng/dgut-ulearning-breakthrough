## 4. 技术资产（这是本轮最有价值的部分）

### 4.1 优学院接口实况（DGUT，路径前缀模式）

| 用途 | 方法与路径 | 备注 |
|---|---|---|
| 课堂活动列表 | `GET /courseapi/wisdomClassroom/student/classroomActivitys?classroomId=&pageSize=&pageNum=&type=1` | ⚠️ 前缀是 **courseapi**，不是 classroomapi（H5 配置模块 API_HOST）。返回结构尚未实测（B1） |
| 投票详情 | `GET /apps/voteV2/detail/{voteId}/{userId}/{classId}` | 来自 H5 模块 KfuA；base = API_HOST_OLD(`/apps`)，404 实测证明它不在 courseapi 下 |
| 投票提交 | `POST /apps/voteV2/stuSubmit` | body `{userId, classIds:-1, optionIds:[…], voteId}` |
| 答题详情 | `GET /classroomapi/replyquestion/student/detail/{id}` | 来自 H5 模块 uwO2；base = SMART_API_HOST = **`https://application.dgut.edu.cn/classroomapi`**（不是 lms 域）。App 里以 `/smartapi/…` 前缀映射过去，lms 域的 `/classroomapi` 作兜底 |
| 答题提交 | `POST /replyquestion/stuReply` | body `{replyoptionId, optionIds:[…]}`；★ `optionIds` 放的是 **option.id（数值升序）**；服务端返回的 `myAnswer` 才是 value 串，H5 先翻成 id 再提交 |
| 答题改答案 | `POST /replyquestion/stuChangeReply` | 同上（`replyquestion.status === 0` 才进行中，与签到 state 语义相反） |
| 作业列表 | `GET /courseapi/homeworks/student?pageNum=&pageSize=` | 已确认存在 |
| 作业提交 | `POST /courseapi/homeworks/submit` | GET 回 405，字段未知 |
| 签到相关 | 见根目录 `youxue-api-verified.md`（非常完整，含踩坑） | |

**活动类型码**（从 H5 源码挖出）：`{1:点名, 2:投票, 3:抢答, 4:选人, 5:打分, 9:讨论, 14:拍照上传, 18:答题}`。

**可达性实测**：`/apps/*` 未登录一律 401（先拦后路由，不可判别）；`/classroomapi/*` 与 `/courseapi/*` 可判别（bogus → 404，真实路径 → 401/405）。
**401 = 路径存在**，404 HTML = 不存在（Tomcat 错误页）。

### 4.4 鉴权与请求层

- 会话：WebView 登录后读 cookie（`services/webCookie.ts`），写回 CookieManager
- 请求：`services/checkin/http.ts` + `signApi`（`sign.actions.rawApi({path, method, body})`）
- ⚠️ `rawApi` 过授权闸（`denyStatusChange()`）：没授权码发不出写请求 —— 新功能要复用它，不要自己 fetch，否则绕过门槛
- 伪造风险点：`signApi` 的请求头必须带移动端 UA / Referer 等（见 `youxue-api-verified.md`）

原生模块注意（踩过）：Kotlin 模块放 `android-native/`，由 `tools/android/wire-native.cjs` 在 prebuild 后接入；**不要直接改 `android/` 下的生成文件**（会被覆盖）。wire-native 现在会先清理历史残留再幂等打补丁。

两条 2026-10-31 补的坑：
1. **manifest 里的自定义 Service 一律写全名**。写成相对名 `.delivery.X` 会按 namespace（applicationId）展开，和 Kotlin `package` 声明不一致 → `ClassNotFoundException` 杀进程（就是 B3 的启动闪退）。目录结构不决定类名，Kotlin 只认文件里的 `package`。
2. **`.gitignore` 里 `android/` 要写成 `/android/`**。不带前导斜杠会匹配任意层级，把 `tools/android/`（build-apk / wire-native / get-sdk）整目录忽略掉 —— 构建脚本因此一直没进 git。已修正，`tools/android/` 现在该跟踪。

## 8. 已知问题 / 坑

0. **⚠️⚠️ restart = 重置活动统计（2026-10-31 实测，造成过一次数据丢失）**：
   对已结束的投票调 `POST /apps/voteV2/restart/{voteId}` 之后，该投票票数从 `42/43/12` 变成 `0/0/0`，截止时间也被清空；`PUT /apps/voteV2/end/{voteId}/{userId}` 只能把状态改回"已结束"，**票数回不来**（已确认被覆盖，不是视图问题）。
   所以：**不要把任何"重开活动"类接口接到 UI**；「已结束后提交」这条路在服务端是 202/201 拒绝，没有安全绕法。
   UI 里的「重开活动 / 恢复为已结束」已删除，`interactionApi.restartVote/restartAnswer/endVote/endAnswer` 保留但注明"会清空数据、勿接回界面"，回归 `tools/verify-vote-feature.cjs` 里有反向断言（UI 再出现这些调用就报红）。
   留下的只读排查工具：投票/答题页底部「按 ID 查投票详情」（纯 GET，用来确认某条记录是否还在）。

1. **启动闪退**（华为 Mate 70 Pro/HarmonyOS）：**229 已修**。真因不是 JS、不是内存，也不是系统杀进程，而是 manifest 里 NotificationListenerService 写成相对名 `.delivery.DeliveryNotificationListener`，按 namespace 展开成 `com.lifekit.app.test.delivery.*`，而 Kotlin 类实际在 `com.lifekit.delivery.*`（dex 已确认）→ `handleCreateService` 每次抛 ClassNotFoundException 直接杀进程。留给后人的教训：manifest 里的 `<service android:name>` 宁写全名；目录不决定类名，Kotlin 只认文件里的 `package`。回归见 `tools/verify-delivery-listener.cjs`。
2. **签到按钮已删**：签到记录页只留「改状态」（`signByStu` 那条路用户说不好用）。
3. **「点不中」入口已隐藏**：页面 `/dianbuzhong` 与路由保留，恢复只需把 `src/screens/xiaocao.tsx` 里注释的 OpRow 取消注释。
4. **投票活动列表 0 条**：接口通但字段没对上（B1），0 条时页面会显示原始返回，便于继续改。
5. **万能码**：只存哈希；`check-master-code-bundle` 现在语义是"发布包不该带明文码"。
